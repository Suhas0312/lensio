# Architecture

## 1. The big picture

```
                   ┌──────────────────────────── Render (one Docker service) ───────────────────────────┐
 Android app ──┐   │  Express API  /v1/*                                                                  │
 (Expo, APK)   │   │   ├─ auth, catalog, lens, prescriptions, cart, orders, payments, shipping, assistant │
               ├──▶│   ├─ admin API  /v1/admin/*                                                          │──▶ Neon PostgreSQL
 Web app ──────┘   │  Static:                                                                             │──▶ Cloudflare R2 (photos, prescriptions)
 (same code,       │   ├─ /          web app (built from mobile/, in backend/public/web)                  │──▶ Brevo (email)
  iPhone/desktop)  │   ├─ /admin     admin panel (plain HTML/JS, backend/public/admin)                    │──▶ Google Gemini (AI assistant)
                   │   └─ /download  Android download page (server-rendered)                              │──▶ optional: Razorpay, Shiprocket,
 Staff browser ───▶│                                                                                      │     WhatsApp Cloud API, MSG91
                   └──────────────────────────────────────────────────────────────────────────────────────┘
```

A single backend serves the API, the admin panel and the web app, so there is one deploy, one domain and no browser cross-origin issues. The web app calls `/v1` relative to wherever it is opened.

## 3. Data model (PostgreSQL via Prisma)

| Model | Purpose |
|---|---|
| `User` | Customer or staff. `email` + `passwordHash` (scrypt), optional `phone`, `role` (CUSTOMER / ADMIN / OPTICIAN) |
| `OtpCode` | Hashed 6-digit codes for email (or SMS) sign-in; expiry, attempt counter |
| `Address` | Delivery addresses. A snapshot is copied onto each order |
| `Product`, `FrameVariant`, `ProductImage` | Frames; variants = colour × size with stock and optional price difference |
| `WishlistItem` | Saved frames |
| `LensPackage`, `Coating` | Lens options and add-ons with prices and power limits |
| `Prescription` | Uploaded photo (private R2 key) or manual values, including optional near-vision SPH (`odNear`/`osNear`), from which ADD is derived when blank; review status |
| `CartItem` | Frame variant + lens + coatings + prescription (or "send later") |
| `Order`, `OrderItem` | Orders with price breakdown frozen at checkout |
| `Payment` | Razorpay, manual UPI (UTR + optional screenshot) or COD records |
| `OrderStatusEvent` | History of stage changes |
| `TrackingUpdate` | Courier scans (Shiprocket) and manual shop updates for live tracking |
| `Coupon`, `CouponUse` | Discounts (e.g. FIRST10) |
| `Setting` | Key/value shop settings edited in the admin panel |
| `Review` | Verified-buyer reviews (one per product per order). `Product.rating/ratingCount` are recomputed from approved reviews |
| `PointsEntry` | Ledger of every loyalty-point change. `User.pointsBalance` is a cached total, kept in sync in the same transaction |
| `GiftCard`, `GiftCardRedemption` | Stored-value codes and each use against an order. Balances are decremented with a conditional update, so they can't go negative |
| `Store` | Physical store locations for the locator |
| `EyeTestRequest` | Home eye-test booking requests (a lead for staff to schedule) |
| `WebhookEvent` | Idempotency for payment webhooks |

**Money is always integer paise** (₹1 = 100). Prices are always calculated on the server (`lens/pricing.ts`, `cart/quote.service.ts`), never trusted from the app.

**Schema changes:** `start.sh` runs `prisma migrate deploy` when `prisma/migrations/` exists, otherwise `prisma db push`. Production currently uses `db push` and only additive changes have been made. **Before making non-additive changes (renames, drops), switch to migrations:** run `npx prisma migrate dev --name baseline` against a copy of production, commit `prisma/migrations/`, then deploy.

## 4. Key flows

### Checkout and stock
1. `POST /v1/orders/checkout` takes a per-user Postgres advisory lock, so double taps can't create two orders.
2. It re-prices the cart, validates the coupon and COD limit, and **atomically decrements stock** (`stock >= qty` condition).
3. It creates the order, items, first status event and payment record, then clears the cart.
4. Online and manual-UPI orders start as `PAYMENT_PENDING` with `holdExpiresAt`. `jobs/runner.ts` cancels expired holds and returns the stock.

### Order state machine (`orders.service.ts → transition`)
`PAYMENT_PENDING → PLACED → PRESCRIPTION_VERIFIED → LENS_CUTTING_FITTING → QUALITY_CHECK → DISPATCHED → DELIVERED`. Any early stage can move to `CANCELLED`.
- Moves are validated against an allow-list. A QC failure can go back to lens cutting.
- Lens orders can't pass prescription verification until every prescription is `VERIFIED`.
- Every move writes an `OrderStatusEvent` and notifies the customer by email (Brevo) and WhatsApp (if configured).
- `DISPATCHED` books Shiprocket if configured. `CANCELLED` restores stock and refunds Razorpay payments.

### Manual UPI payments (no gateway fees)
1. `settings.service.ts` builds a standard `upi://pay` link (pa, pn, am, cu, tn) and a QR with the exact amount.
2. The customer pays and submits the 12-digit UTR, optionally with a screenshot, via `POST /orders/:id/upi-payment`. This pauses the hold timer.
3. Staff confirm or reject in the admin panel. Confirming moves the order to `PLACED`.

### Prescriptions
- `rx.rules.ts` validates ranges and 0.25 D steps, requires AXIS when CYL ≠ 0 and ADD for bifocal/progressive, transposes plus-cylinder to minus-cylinder, and flags high power. It is covered by tests.
- Uploaded images are **private**. They are shown only through signed URLs that expire in 10–30 minutes.
- Opticians review in the admin panel's Prescriptions queue.

### Authentication
- Email + password (scrypt, salted) or a 6-digit email code (hashed, 10-minute expiry, 5 attempts, rate-limited). The same code flow resets passwords.
- The server issues a JWT (default 30 days). Phones store it in the keychain; browsers use localStorage.
- Admins are defined by `ADMIN_EMAILS`, and are promoted on their next sign-in. Password hashes are never returned by the API.

### AI assistant (`modules/assistant`)
- For every question, the server builds a context from the database: active catalog (up to 60 frames), lens packages, coatings, payment options, the owner's "shop information" from Settings, and **the signed-in customer's own last 5 orders**.
- A system prompt fixes the rules: only recommend listed frames, no medical advice or diagnosis, send returns and complaints to WhatsApp.
- It calls Gemini (`GEMINI_MODEL`, default `gemini-2.5-flash`). If there's no key, or Gemini errors, it falls back to rule-based answers.
- Frame names in the reply become product cards. A `[HANDOFF]` tag in the reply shows a WhatsApp button.
- Rate limits are 10 requests/minute and 150/day per IP.

### Instagram import (`modules/instagram`)
- Uses the **Instagram API with Instagram Login** (`graph.instagram.com/me/media`) with a long-lived token. The token is refreshed weekly by the job runner, via `refresh_access_token`.
- `caption.ts` reads captions into a product guess (tested). The admin confirms or edits before importing.
- Instagram CDN image URLs expire, so photos are **copied to R2** on import. `Product.instagramPostUrl` stores the permalink, which prevents duplicates and powers "View on Instagram".

### Review requests
`jobs/runner.ts → sendReviewRequests` runs every 3 hours. It finds orders delivered 2 or more days ago with `reviewRequestedAt = null`, marks them first (so they never repeat), and emails the ones not yet reviewed.

### Loyalty points and gift cards
- **Quote:** `buildQuote` previews them read-only. Points come first, capped at `loyaltyMaxRedeemPercent` of the subtotal; the gift card then covers what's left, including delivery.
- **Checkout:** debits both inside the order transaction (`debitPoints`, `redeemGiftCard`), so the preview and the debit can't disagree.
- **Earning:** `pointsEarned` is fixed at checkout from what was paid for goods, and credited on `DELIVERED`. Crediting is idempotent per order.
- **Cancellation:** reverses every points entry for the order and refunds gift-card redemptions.
- A ₹0 total (fully covered) places the order straight away, with no payment step.

### Live tracking
- The order screen polls `GET /orders/:id` every 20 seconds while open.
- `tracking.ts` estimates delivery: about 4 days for frame-only orders, about 7 days with lenses, adjusted by stage, and never a past date.
- `TrackingUpdate` rows come from the Shiprocket webhook (courier scans) or the admin panel (manual updates, which also email the customer).

### AI try-on (`backend/public/tryon`)
- A plain HTML/JS page at `/try-on`. The web app shows it in an iframe, and the phone apps in a WebView (`react-native-webview`); messages open products and hand back captured photos.
- **face-api.js** (MIT, self-hosted with its models in `public/tryon/models`) runs in the browser: TinyFaceDetector plus 68 landmarks. **No images leave the device.**
- **Placement:** frame width = eye distance × (frame width in mm ÷ 62 mm average PD), rotated to the eye line and smoothed in live video. Customers can drag or pinch; Auto-fit resumes after 3 seconds.
- **Face shape** comes from landmark ratios (round, square, oval, heart or long) and sorts "Suits you" frame shapes first. It's styling guidance, not a measurement.
- **Frame images:** `GET /v1/catalog/products/:id/tryon-image` serves the uploaded PNG or the main photo from the same server. The page removes near-white background pixels, crops and caches the result.
- **Capture** draws the camera or photo plus the frame onto a canvas, then uses Web Share, download, or the app's share sheet.

### Voice search
`expo-speech-recognition` works on Android, iOS and browsers. `lib/voiceQuery.ts` turns speech into filters: shape, gender, size, sunglasses, price ranges ("under 2000", "between 1k and 3k") and sort. Leftover words become the text search.

## 5. Web app specifics
- One codebase. `Platform.OS === 'web'` switches token storage, alerts (`lib/webPolyfills.ts`), file uploads (`lib/files.ts`) and install banners.
- `lib/layout.ts → useLayout()` gives responsive grids: 2 columns on phones, then 3, 4 and 5 on wider screens. Forms use a 760 px column.
- The build is a static export (`web.output: single`). The backend serves `index.html` for page routes and caches hashed bundles for a year.
- There is a PWA manifest and icons, so it can be installed from Chrome and added to the home screen on iPhone.

## 6. Security and privacy
- **Security headers (helmet) with a strict CSP:** scripts from same origin only, and connections to same origin plus blob/data for photo uploads. The admin panel has no inline scripts because of this.
- **Rate limits** apply to all APIs, and are tighter on sign-in, codes and the assistant.
- **Secrets live only in environment variables.** None are in the repository. `.env` is git-ignored.
- **Prescriptions and payment screenshots** are stored privately in R2.
- **Personal data processed:** name, email, phone, address, prescription values and images, and order history. The privacy policy must cover this, including that the AI assistant sends catalog data and the customer's own order summary to Google Gemini. **On Gemini's free tier, Google may use prompts to improve its services.** For stricter privacy, move to a paid Gemini tier or another provider (the change is in `assistant.service.ts → askGemini`).
- Prescriptions are health information. Google Play's Data Safety form and any App Store listing must declare them.
